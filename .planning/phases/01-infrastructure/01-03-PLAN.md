<task type="auto">
  <name>Task 1: Deploy to Vercel and push schema to Supabase</name>
  <files></files>
  <action>
    **Step 1: Link Supabase project and push schema**

    Ensure the user has created a Supabase project and has the project ref. Then:
    ```bash
    pnpm supabase link --project-ref "$SUPABASE_PROJECT_ID"
    pnpm supabase db push
    ```

    Verify the migration applied:
    ```bash
    pnpm supabase migration list
    ```
    The initial_schema migration should show as "applied."

    **Step 2: Deploy to Vercel**

    If the Vercel CLI is not installed:
    ```bash
    pnpm add -g vercel
    ```

    Deploy:
    ```bash
    vercel --yes
    ```

    This will prompt for project linking on first deploy. After deployment, set environment variables in Vercel project settings. Use the CLI:
    ```bash
    vercel env add NEXT_PUBLIC_SUPABASE_URL production
    vercel env add NEXT_PUBLIC_SUPABASE_ANON_KEY production
    vercel env add SUPABASE_SERVICE_ROLE_KEY production
    vercel env add NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY production
    vercel env add CLERK_SECRET_KEY production
    ```

    After setting env vars, trigger a redeployment:
    ```bash
    vercel --prod --yes
    ```

    **Step 3: Verify the deployment**

    ```bash
    curl -s -o /dev/null -w "%{http_code}" https://<deployment-url>
    ```
    Should return 200.

    If the build fails, check:
    1. Missing environment variables (most common cause)
    2. TypeScript errors (run `npx tsc --noEmit` locally first)
    3. Import path issues
  </action>
  <verify>
    <automated>vercel ls 2>&1 | head -5 && echo "---" && curl -s -o /dev/null -w "%{http_code}" $(vercel inspect --json 2>/dev/null | grep -o 'https://[^"]*' | head -1) 2>/dev/null || echo "Check Vercel dashboard for deployment status"</automated>
  </verify>
  <done>
    - Supabase migration pushed to production
    - Vercel deployment succeeds (no build errors)
    - All 5 environment variables set in Vercel
    - Production URL responds with 200
  </done>

<task type="checkpoint:human-action" gate="blocking">
  <name>Task 2: Configure Clerk third-party auth in Supabase dashboard</name>
  <files>src/constants/user.ts, supabase/config.toml</files>
  <action>
    This is a HUMAN ACTION checkpoint — the following steps require dashboard access that Claude cannot automate.

    **Setup steps (must be done in this order):**

    1. **In Clerk Dashboard:**
       - Go to Settings > Integrations > Supabase (or search for "Supabase")
       - Enable the Supabase integration
       - Note your Clerk instance domain (e.g., `your-app.clerk.accounts.dev`)

    2. **In Supabase Dashboard:**
       - Go to Project Settings > Authentication > Third-Party Auth
       - Click "Add Provider"
       - Select Clerk (or "Custom JWT")
       - Paste your Clerk instance domain
       - Save

    3. **Update `src/constants/user.ts`:**
       - Sign into your Clerk app
       - Find your Clerk user ID (visible in Clerk Dashboard > Users, or in the JWT payload)
       - Replace `'user_PLACEHOLDER'` with your actual Clerk user ID (e.g., `'user_2w2a6PJC4T4BfXDsg72AQsLNEyU'`)

    4. **Update `supabase/config.toml`:**
       - Replace `domain = "example.clerk.accounts.dev"` with your actual Clerk domain

    5. **Redeploy after changes:**
       ```bash
       vercel --prod --yes
       ```
  </action>
