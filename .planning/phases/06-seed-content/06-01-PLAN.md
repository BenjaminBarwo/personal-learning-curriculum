    Content requirements for this lesson:
    - **Hook**: In 2014, Bahdanau introduced a simple idea that changed sequence modeling forever — instead of compressing an entire sentence into a single vector, let the model look back at all input positions when generating each output word. This "attention" concept became the foundation of the transformer.
    - **ConceptBlock 1 "The Bottleneck Problem"**: Before attention, encoder-decoder models compressed the entire input into a fixed-size context vector. Long sequences lost information. The last hidden state had to carry everything. Include `<Definition term="context vector">`.
    - **ConceptBlock 2 "Scaled Dot-Product Attention"**: The core computation: Query, Key, Value matrices. Dot product of Q and K gives attention scores, scale by sqrt(d_k), softmax to get weights, multiply by V. Include `<Definition term="query">`, `<Definition term="key">`, `<Definition term="value">` definitions. The scaling prevents softmax saturation.
    - **ConceptBlock 3 "Multi-Head Attention"**: Instead of one attention function, run multiple in parallel with different learned projections. Each "head" learns to attend to different types of relationships (syntactic, semantic, positional). Include `<Definition term="multi-head attention">`. Concat heads and project through a linear layer.
    - **ConceptBlock 4 "Self-Attention vs Cross-Attention"**: Self-attention: Q, K, V all come from the same sequence (encoder attending to itself, or decoder attending to itself). Cross-attention: Q from decoder, K and V from encoder output — this is how the decoder "reads" the encoder. Include `<Definition term="cross-attention">`.
    - **ConceptBlock 5 "Attention in Practice"**: Modern variants — Flash Attention for efficiency, sparse attention for long sequences, grouped-query attention in Llama. The attention mechanism is the most actively researched component.
    - **Diagram**: A flowchart showing the attention computation. Use `flowchart TD` (top-down). Show: Input -> split into Q, K, V -> MatMul(Q, K^T) -> Scale -> Softmax -> MatMul with V -> Output. Keep it clean and readable.
