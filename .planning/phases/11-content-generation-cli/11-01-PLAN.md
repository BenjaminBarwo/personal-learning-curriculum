       - `LessonTarget` interface: `{ id: string, name: string, slug: string, courseSlug: string, courseName: string, pillarSlug: string, pillarName: string, semesterSlug: string, semesterNumber: number, displayOrder: number, mdxContent: string | null }`

    3. Create `scripts/lib/anthropic.ts` — Anthropic client singleton:
       - Import `Anthropic` from `@anthropic-ai/sdk`
       - Export `anthropic` instance with `maxRetries: 3` and `timeout: 120_000`
       - Use `process.env.ANTHROPIC_API_KEY` (loaded via dotenv in entry point)

    4. Create `scripts/lib/retry.ts` — manual backoff for 529 errors:
       - Export `withBackoff<T>(fn: () => Promise<T>, maxAttempts = 3): Promise<T>`
       - Catch errors, check `err instanceof Anthropic.APIError && err.status === 529`
       - Delay: `1000 * 2 ** (attempt - 1)` (1s, 2s, 4s)
       - Log retry attempts with `console.warn`
       - Re-throw on final attempt or non-529 errors
       - Import `Anthropic` from `@anthropic-ai/sdk` for `APIError` type check

    5. Create `scripts/lib/supabase.ts` — admin Supabase client for CLI:
       - Import `createClient` from `@supabase/supabase-js`
       - Import `Database` type from `../../src/types/database.types` (relative path, NOT @/ alias)
       - Export `supabase` instance using `process.env.NEXT_PUBLIC_SUPABASE_URL` and `process.env.SUPABASE_SERVICE_ROLE_KEY`
       - Set `auth: { persistSession: false }`
       - Do NOT import from `@clerk/nextjs/server` — this is a CLI context, no Clerk (see Pitfall 1 in RESEARCH.md)

    6. Create `scripts/lib/progress.ts` — tree-style progress display:
       - Export `printLessonHeader(current: number, total: number, title: string): void` — prints `\n[{current}/{total}] '{title}'`
       - Export `printStage(stage: string, status: 'start' | 'done' | 'fail', durationMs?: number): void`:
         - `start`: prints `  ├ {stage}...` (no newline, use `process.stdout.write`)
         - `done`: prints ` done ({seconds}s)\n`
         - `fail`: prints ` FAILED\n`
       - Export `printSummary(results: PipelineResult[]): void` — prints post-run report:
         - Count generated, skipped, failed
         - List failures with error messages
         - Total duration

    IMPORTANT: All files use ESM imports (`import`/`export`). Do NOT use `require()`. TypeScript will be executed via `tsx` which handles ESM natively.
