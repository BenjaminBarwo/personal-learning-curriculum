  <action>
    1. Create `scripts/pipeline/research.ts`:
       - Export `researchTopic(params: { topic: string, pillarName: string, courseName: string, model: string }): Promise<string>`
       - Call `anthropic.messages.create()` with:
         - `model: params.model`
         - `max_tokens: 4096`
         - `tools: [{ type: 'web_search_20250305', name: 'web_search', max_uses: 5 }]` — per Pitfall 6 in RESEARCH.md, use versioned tool name
         - User message: research prompt asking for 3-5 concrete real-world examples, recent developments, key concepts, and cross-domain connections for the topic in context of the pillar/course
       - Wrap the call in `withBackoff()` for 529 protection
       - Extract text content from the response (handle both text blocks and tool_result blocks)
       - If web_search tool is unavailable (API error), fall back gracefully: log warning and return a message asking Claude to use training knowledge instead (do NOT crash)
       - Return the research notes as a string

    2. Create `scripts/pipeline/generate-lesson.ts`:
       - Export `generateLesson(params: { lessonTarget: LessonTarget, researchNotes: string, priorLessonSummaries: string[], model: string, totalLessons: number }): Promise<{ mdx: string, quizQuestions: GeneratedQuizQuestion[] }>`
       - Build system prompt via `buildSystemPrompt()`
       - Use streaming: `anthropic.messages.stream()` with `max_tokens: 8192` — use stream to avoid idle connection timeout on long generations (per RESEARCH.md recommendation)
       - Await `stream.finalMessage()` to get the full response
       - Parse the response to extract MDX content (between ```mdx markers) and quiz questions JSON (between ```json markers)
       - If parsing fails (Claude didn't use the expected format), attempt to extract the MDX as the full text content and log a warning about missing quiz questions
       - Wrap the entire call in `withBackoff()`
       - Return `{ mdx, quizQuestions }`

    3. Create `scripts/pipeline/review-lesson.ts`:
       - Export `reviewLesson(params: { mdx: string, quizQuestions: GeneratedQuizQuestion[], lessonTarget: LessonTarget, priorLessonSummaries: string[], model: string }): Promise<{ mdx: string, quizQuestions: GeneratedQuizQuestion[] }>`
       - Build review prompt via `buildReviewPrompt()`
       - Call `anthropic.messages.create()` (not streaming — review responses are shorter) with `max_tokens: 8192`
       - Parse the response same way as generate (extract MDX and quiz JSON)
       - If the reviewer returns the original unchanged, use the original (avoid unnecessary changes)
       - Wrap in `withBackoff()`
       - Return `{ mdx, quizQuestions }`

    4. Create `scripts/pipeline/validate-mdx.ts`:
       - Export `validateMdx(mdxContent: string): Promise<{ valid: boolean, errors: string[] }>`
       - Stage 1: Parse check — call `compile(mdxContent, { jsx: true })` from `@mdx-js/mdx`. If it throws, push parse error to errors array and return immediately.
         NOTE: Use `jsx: true` (not `jsx: false`) so the compiler accepts JSX component tags without requiring imports. The MDX content uses custom components (Hook, ConceptBlock, etc.) that are provided at render time, not import time.
       - Stage 2: Component presence check — for each of `['Hook', 'ConceptBlock', 'Quiz', 'DeepDive', 'Exercise', 'Takeaways']`, test if the MDX string contains `<ComponentName` (regex: `/<ComponentName[\s>\/]/`). Push missing component errors.
       - Note: `Definition`, `Diagram`, and `Video` are OPTIONAL — do not fail validation if missing. Only the 6 core structural components are required per GEN-02.
       - Return `{ valid: errors.length === 0, errors }`

    IMPORTANT:
    - All pipeline functions are pure — they take input, call Claude/validate, return output. No side effects (no DB writes, no file writes).
    - All Claude calls go through `withBackoff()` from scripts/lib/retry.ts for 529 protection.
    - Use `import type` for type-only imports.
    - Per CONTEXT.md: sequential generation, one lesson at a time. These functions are called sequentially by the orchestrator (Plan 03).
