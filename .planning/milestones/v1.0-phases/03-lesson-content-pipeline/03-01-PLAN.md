**Client Components (MUST have 'use client'):**

5. **DeepDive.tsx** — Expandable deep-dive accordion section.
   Props: `{ title: string; readingMinutes?: number; id?: string; children: React.ReactNode }`
   Behavior (per user decisions — NON-NEGOTIABLE):
   - Collapsed by default — learner sees title + teaser only
   - Show `~X min read` next to expand trigger when `readingMinutes` is provided
   - Accordion behavior: one DeepDive open at a time, opening one collapses the previous

   Implementation: Use a `DeepDiveContext` to manage shared state. Create a `DeepDiveProvider` wrapper that tracks `openId: string | null`. Each DeepDive reads from context and calls `setOpenId(myId)` on expand (sets to null on collapse). Generate a stable ID from the title if `id` prop not provided (use a simple hash or index). Export `DeepDiveProvider` from this file.

   Expand/collapse animation at Claude's discretion. Include an expand/collapse icon (chevron or similar).

6. **Definition.tsx** — Inline term definition with click-to-expand.
   Props: `{ term: string; children: React.ReactNode }`
   Behavior (per user decisions — NON-NEGOTIABLE):
   - Clicking the term expands the definition right below the word in the text flow
   - One definition open at a time — expanding a new one auto-collapses the previous
   - Dismiss by clicking anywhere outside the expanded definition

   Implementation: Use a `DefinitionContext` to manage shared state (tracks `openTerm: string | null`). Create a `DefinitionProvider` wrapper. Each Definition reads from context and calls `setOpenTerm(term)` on click (null to close). Add a `useEffect` with a click-outside listener on the document that sets `openTerm` to null when clicking outside any definition.

   Visual styling at Claude's discretion but MUST work in both dark and light mode. The term itself should be visually distinct from surrounding text (e.g., dotted underline, highlighted, or subtly different color). The expanded definition should appear inline below the term, not as a tooltip/popover.

   Export `DefinitionProvider` from this file.

7. **Diagram.tsx** — Client-only Mermaid diagram renderer.
   Props: `{ chart: string; caption?: string }`
   Behavior (per user decisions — NON-NEGOTIABLE):
   - Auto-themed to match dark/light mode
   - Optional caption below diagram

   Implementation:
   - Import mermaid ONLY inside `useEffect` via `await import('mermaid')` — NEVER at module level (crashes SSR)
   - Use `useTheme()` from next-themes to get `resolvedTheme`
   - Call `mermaid.initialize({ startOnLoad: false, theme: resolvedTheme === 'dark' ? 'dark' : 'default' })`
   - Call `mermaid.render(id, chart)` to get SVG string
   - Re-render when theme changes (include `resolvedTheme` in useEffect deps)
   - Show a loading placeholder while rendering
   - Handle render errors gracefully (show fallback text, do NOT crash)
   - Use `dangerouslySetInnerHTML` to insert the SVG
   - Wrap in `<figure>` with `overflow-x-auto` for mobile (per Claude's discretion on mobile behavior)
   - Render `<figcaption>` only when `caption` is provided

   CRITICAL: Must guard against `resolvedTheme` being `undefined` on first render (mounted check).

8. **Video.tsx** — Click-to-play video embed.
   Props: `{ url: string; caption?: string }`
   Behavior (per user decisions — NON-NEGOTIABLE):
   - Support any video URL — YouTube, Vimeo, or direct mp4/webm links
   - Click-to-play thumbnail — show a poster image, only load iframe/player on click

   Implementation:
   - Import `ReactPlayer` from `react-player/lazy` (NOT default import — avoids loading all player types upfront, per Pitfall 6 in research)
   - Use `light={true}` prop for click-to-play poster behavior
   - Set `width="100%"` and `height` to a reasonable aspect ratio
   - Wrap in a container div with optional caption
   - Use `controls={true}` for player controls after activation

   Wrapper/caption design at Claude's discretion.
