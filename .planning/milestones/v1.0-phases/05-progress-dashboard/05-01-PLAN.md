    **1. Create `src/lib/progress.ts`** — Server-side progress computation module. Export these functions:


    **`getLessonProgressForScope(supabase, lessonIds, userId)`**
    - Accept a Supabase client instance (the caller's server client), an array of lesson ID strings, and a userId string
    - Return `{ completed: number; total: number; percent: number }`
    - If lessonIds is empty, return `{ completed: 0, total: 0, percent: 0 }`
    - Query `progress` table: `.select('id', { count: 'exact', head: true })` with `.eq('user_id', userId)`, `.eq('status', 'completed')`, `.in('lesson_id', lessonIds)`
    - Calculate percent as `Math.min(100, Math.round((completed / total) * 100))`
    - Use `head: true` optimization — no row data transferred, only count

    **`getContinueLesson(supabase, userId)`**
    - Query `progress` table: `.select('lesson_id, last_accessed_at')` with `.eq('user_id', userId)`, `.neq('status', 'completed')`, `.order('last_accessed_at', { ascending: false })`, `.limit(1)`, `.maybeSingle()`
    - If found, query `active_lessons` to get `id, name, slug, course_id`
    - Then resolve the full URL path by querying the course -> semester -> pillar chain to get their slugs
    - Return `{ lessonName, lessonSlug, courseName, courseSlug, semesterSlug, pillarSlug, pillarColor, href } | null`
    - The href should be the full path: `/pillars/${pillarSlug}/semesters/${semesterSlug}/courses/${courseSlug}/lessons/${lessonSlug}`

    **`markLessonInProgress(supabase, lessonId, userId)`**
    - First check if the lesson already has a progress row: `.from('progress').select('status').eq('user_id', userId).eq('lesson_id', lessonId).maybeSingle()`
    - If existing status is `'completed'`, return early (do NOT overwrite completed with in_progress)
    - Otherwise upsert: `.from('progress').upsert({ user_id: userId, lesson_id: lessonId, status: 'in_progress', started_at: existing ? undefined : new Date().toISOString(), last_accessed_at: new Date().toISOString() }, { onConflict: 'user_id,lesson_id' })`
    - This is fire-and-forget — catch and log errors but do not throw (should not block page render)

    **`isSemesterLocked(semesterIndex, semesterProgressList, manuallyUnlocked)`**
    - Pure function, no DB access
    - semesterIndex: number (0-based position in display_order-sorted list)
    - semesterProgressList: `Array<{ percent: number }>` — parallel array of progress per semester
    - manuallyUnlocked: boolean — whether this specific semester has the override flag
    - Returns boolean: `true` if locked
    - Logic: index 0 is never locked; if manuallyUnlocked is true, return false; otherwise return `semesterProgressList[semesterIndex - 1].percent < 100`

    **`getLessonStatuses(supabase, lessonIds, userId)`**
    - Query progress for all given lesson IDs in a single query: `.from('progress').select('lesson_id, status').eq('user_id', userId).in('lesson_id', lessonIds)`
    - Return `Map<string, LessonStatus>` mapping lesson_id -> status
    - Lessons not in the map are implicitly 'not_started'

    All functions should use the Supabase client passed as a parameter (not create their own). The caller (each page) creates the client and passes it in. Import `LessonStatus` from `@/types/database.types`.
